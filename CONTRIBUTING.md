# How to contribute

Thank you for your interest into Capytaine.

## Contact

The best place to report a bug or to propose an enhancement is the [issue
tracker](https://github.com/capytaine/capytaine/issues) of Capytaine's Github
repository.

The [discussion page](https://github.com/capytaine/capytaine/discussions) can
also be used to ask questions and submit ideas.

## Submitting changes

Pull requests are welcome.

For significant changes, please open an issue or discussion thread beforehand
for the maintainers to agree upon it.

See the [developer manual](https://capytaine.org/master/developer_manual) for
more instructions.

## AI Policy

It is fine to use an LLM as support, for example to help understand the existing codebase,
review human-written changes, or help with translation or grammar.

It is acceptable to use an LLM to generate code only if:

- A human drove the tool, reviewed every line, responds to review comments personally,
  can explain the changes and take responsibility for them.
- The PR clearly states that it is AI-assisted and names the tool used.
- Only humans are credited as co-authors. The Linux kernel trailer should be used
  to credit AI assistance, like this: `Assisted-by: <harness>:<model>`.

When writing an issue or PR, a few lines of your own words are usually preferred
to pages of generated text.

It is not acceptable to submit unread raw LLM output.
